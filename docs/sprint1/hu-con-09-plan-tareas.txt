1. CONTEXTO
-----------
  Es la primera historia de la cadena del Sprint 1: la HU-CON-01 (registrar
  venta confirmada) necesita el porcentaje vigente para que la HU-CON-02
  calcule la comisión.

  Historia: como Administrador financiero quiero configurar el porcentaje de
  comisión con fechas de vigencia, para que cada venta se liquide con el
  porcentaje vigente en su fecha y quede trazabilidad de los cambios.

  Decisión D-04: comisión global con vigencias; el modelo queda preparado
  para alcance VENDEDOR y CATEGORIA con prioridad
  vendedor > categoría > global. Solo el rol ADMIN_FINANCIERO configura.


2. DECISIONES DE ESTA HISTORIA (2026-10-09)
-------------------------------------------
  - Alcance: el dominio, la BD y el puerto CommissionConfigProvider soportan
    GLOBAL, VENDEDOR y CATEGORIA. En el Sprint 1 el PUT y la pantalla solo
    configuran GLOBAL.
  - Vigencias retroactivas permitidas, sin solapamiento: la nueva vigencia
    debe empezar después del inicio de la vigencia abierta del mismo
    alcance/referencia; la anterior se cierra el día previo al inicio de la
    nueva. Si no se cumple -> error CONFLICTO (HTTP 409).
  - Las vigencias son fechas (DATE), día contable en hora de Colombia
    (igual que Periodo.ts). vigente_hasta es inclusive; NULL = abierta.
  - Las ventas ya registradas no cambian: guardan el % aplicado (HU-CON-02).

4. CRITERIOS DE ACEPTACIÓN
--------------------------
  - Solo ADMIN_FINANCIERO puede configurar; el CONTADOR solo consulta.
  - Al registrar una nueva vigencia la anterior queda cerrada el día previo.
  - Nunca hay dos vigencias solapadas para el mismo alcance/referencia.
  - Para cualquier fecha se obtiene el porcentaje vigente en esa fecha.
  - Cada cambio queda en contabilidad.auditoria con usuario y valores.
  - La pantalla muestra el porcentaje vigente y el historial.
